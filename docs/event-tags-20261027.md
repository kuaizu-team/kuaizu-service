## 数据库执行与部署顺序

数据库变更由用户在 `kuaizu_db` 中执行；本仓库保留执行脚本和逐条标签清单，便于复核与回滚。

1. 执行 sql/20261027_event_tags_schema.sql，增加可空 tags 字段（MySQL 5.7+）。
2. 在同一个数据库连接中完整执行 sql/20261027_event_tags_seed.sql；仅填充同 ID、同名称且标签为空的赛事，事务内备份旧标签，补齐共享标签库。已有标签不会覆盖，已改名/不存在的赛事会列为跳过。
3. 后端部署必须在字段新增之后；随后更新后台和小程序。新建/编辑赛事沿用既有权限，标签最多 3 个、每个 1–12 字，禁止重复；省略 tags 保留旧值，[] 或 null 清空。
4. 如需撤销补齐，执行 sql/20261027_event_tags_rollback.sql。它只撤销仍与本次补齐一致的数据，不删除共享标签或字段，不改动截止日期与其他业务字段。
