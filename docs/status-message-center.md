# 状态消息中心

客户端分支：`codex/home-event-short-name`。后端分支：`codex/feishu-user-sync-backend`。

## 数据与展示

`user_status_message` 是独立归档表，复用 `StatusNotificationRepository`。`status_notification` 继续作为原有自动全屏状态页的投递队列。其优先级排序、压制其余通知的 UPDATE、管理员邀请优先规则均保留。

| 字段 | 用途 |
| --- | --- |
| user_id | 归属当前登录用户；所有查询、写入均按此字段限制 |
| type | 11 类消息类型 |
| source_key | 用户范围内的幂等键；同一业务事件不会重复归档 |
| status_notification_id | 可空的原队列关联；不设置业务资源外键，源记录删除后归档仍保留 |
| payload | 可空 JSON 展示快照，不包含手机号、联系方式或认证信息 |
| read_at | 空表示未读；已有时间表示已读 |
| fullscreen_displayed | NULL 为历史未知，0 为未展示，1 为实际展示 |
| fullscreen_displayed_at | 实际展示的首次确认时间，可空 |
| created_at | 业务事件时间，用于倒序展示；同时间按 ID 倒序 |

申请录用/拒绝、橄榄枝录用/拒绝、移出团队在原业务事务内同步归档。选中某条队列通知后，其他通知仍按原方式退出自动展示队列，但它们的归档消息保持未读。原 `displayed` 接口只对真正展示的那条消息确认展示并已读。

项目发布、完成招募、项目结束、人才名片提交、管理员邀请在对应保存事务内归档。完成招募和项目结束由客户端操作时，消息归属实际操作人；管理员操作时使用项目创建者。人才名片只在进入审核状态时归档，审核中编辑不会重复产生提交消息。新增“聊一聊”消息由申请进入互相了解或接收橄榄枝后进入沟通时创建，仅在消息中心回看，不新增自动弹出时机。

消息中心逐条打开原状态页或管理员邀请页，不增加其他详情路由。回看使用快照，避免资源删除、改名或权限变化破坏历史内容。打开成功记录实际全屏展示；详情卸载后标记已读，并在确认成功后再次刷新列表/首页，处理返回与网络请求的时序。未成功加载的详情不会标记已读。历史管理员邀请只供回顾，不能重新提交反馈或修改当前邀请的会话延期状态。

首页红点在首页显示、回到首页、小程序回前台以及返回详情读确认完成后刷新，不轮询。未登录首页不请求未读接口；进入消息中心遵循现有登录跳转。

## API

以下路径相对于 `/api/v2`，沿用 JWT 及账号状态中间件，只允许操作当前用户消息。详细 OpenAPI 位于 `api/service/paths/users_me_messages*.yaml`，手动注册路由与现有状态通知接口保持一致。

| 方法与路径 | 用途 |
| --- | --- |
| GET /users/me/messages?page=1&size=20&read=false | 分页列表；read 可省略；每页上限 50 |
| GET /users/me/messages/:id | 获取当前用户的消息快照 |
| GET /users/me/messages/unread-count | 返回 `{count}` |
| GET /users/me/messages/latest?type=...&projectId=... | 即时状态页查询刚生成的归档；无记录返回 null |
| POST /users/me/messages/:id/read | 幂等标记已读，不修改自动展示队列 |
| POST /users/me/messages/:id/displayed | `{read:false}` 记录回看展示；`{read:true}` 确认正常即时展示并已读 |

不存在及他人消息均返回 404，分页与类型错误返回 400。旧版客户端接口及返回字段保持兼容；待展示响应仅增加可选 `messageId`。

## 迁移与发布

1. 审阅 `sql/20261013_status_message_archive.sql`，先在备份和测试环境核对。脚本交付时未执行，不使用应用启动自动迁移。
2. 人工执行迁移，再部署后端，再发布客户端。后端的归档写入与业务保存共用事务，因此新表必须先存在。
3. 脚本可重复执行。唯一来源键阻止重复导入，冲突更新只保留原键，不重置新消息的已读/展示状态。没有修改原通知队列或其他业务表。

历史恢复范围为现存状态队列、尚可查到的聊一聊时间、项目创建和最近一次完成招募/结束时间、现有人才名片首次记录、尚存或可从反馈推断的管理员邀请。所有恢复记录默认已读，实际展示情况未知；已删除的源记录和多次重复事件无法完整还原。历史项目统计使用迁移时的现有值，无法还原过去每个时点的数值；新消息统计在事件产生时保存。

客户端：在 `miniprogram` 目录运行 `npx tsc -p .. --noEmit` 和 `npm test`。后端：运行 `go test ./internal/repository ./internal/handler ./internal/service ./cmd/server`。
