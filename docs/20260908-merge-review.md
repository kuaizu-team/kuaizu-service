## 可用于合并说明的简报

扩展项目/人才搜索降级匹配与相关性排序，保留单赛事精确筛选，并支持最多 10 个赛事的叠加匹配。完善赛事详情、PV、时间线、独立报名截止日、官网及参赛说明，支持个人、团队、个人/团队均可和人数范围。个人中心按入口聚合红点，看板入口游标与明细游标独立，旧调用保持原行为；邮箱允许留空且保留非空格式校验。

合并前修复四项审核问题：赛事资源仅在现有详情接口向当前已通过学生认证且未封禁的用户返回，公开列表与嵌套赛事不携带资料链接和 QQ 群号；旧管理端遗漏的新增字段保留原值，显式清空仍有效；管理端时间线查询失败返回错误；项目/人才搜索最多 32 个 Unicode 字符，并减少重复评分表达式。复用原有路由，未新增路由。客户端补齐认证返回后的资料刷新。

## 本次修复边界

- 鉴权复用原有签名 token 解析，资源权限读取当前数据库认证及封禁状态。数据库查询失败不返回资源；详情设置 `Cache-Control: private, no-store`。
- `Event.ToVO()` 默认不携带受限资料，避免项目详情、推荐、列表等间接返回路径泄漏。管理端使用独立 VO，不受该公开数据投影调整影响。官网等公开字段正常返回。
- 旧端遗漏的主办方、简介、资料池、QQ群、官网、参赛说明、参赛形式、人数边界及跨校跨专业规则保留原值。旧布尔字段的显式修改继续参与规则归一化；个人或未知参赛形式仍按原校验清理人数边界。
- 时间线读取成功且确实无节点时仍返回 `[]`；查询异常返回 500，不再伪装为空列表。保存沿用既有事务全量替换。
- 搜索在 handler 和 repository 两层拒绝超长关键词，不静默截断。完整匹配 4 分、双字匹配 3 分、多字匹配 2 分、单字匹配 1 分的语义保持；使用 `LEAST(2, matchCount)` 避免重复展开计数。32 个不同字符的项目关键词，过滤与评分表达式控制在 180 KB / 1,536 参数以内。此项是 SQL 构造边界，不代表线上数据库耗时。
- 本轮没有修改路由注册、项目状态流转、支付、订单、消息发送、看板游标读写或管理端页面。消息服务中心无需调整。
- 客户端只修改赛事详情的认证返回刷新及相应测试；已有资料时不重复刷新。认证后实际重新请求详情会沿用原 GET 的 PV 计数规则。
