# 名片协作指数与认证交互

## 行为

- 用户徽章通过 `user-id` 启用详情交互；项目里程碑等非用户认证标识不传该属性，保留原行为。徽章点击和弹窗内容拦截冒泡，避免触发外层卡片跳转；弹窗使用 root-portal 和既有底部弹窗风格。
- 协作详情需要登录；弹窗展示具体分数、后端返回的五档区间、当前位置和项目综合分。空评分显示“暂无评分”，0 分显示“0 分”。错误可重试，不以默认 90 分冒充接口结果。
- 本人已认证：仅显示“已完成学校、专业、年级认证”及“好的”，不进入认证页。本人未认证：进入既有认证页。
- 他人名片：展示被查看者的认证说明。点击者已认证时仅“好的”；未认证时提供“我要认证”和“取消”。未登录者点击认证入口先登录。
- 决定是否进入认证页前刷新本人认证状态，避免旧名片数据导致已认证用户重复上传。

## 接口与数据

新增 `GET /users/{id}/collaboration-detail`，走现有 JWT 中间件并在 handler 检查登录身份；任意已登录用户可查看本人或他人。仅返回 userId、score、level、ranges 和 projects，后者仅含 projectId、projectName、score。没有评分者身份、单次评分、认证图片或联系方式。

总体分数直接读取用户现有协作指数，等级使用现有模型：较差 [0,50)、中等 [50,85)、良好 [85,90)、优秀 [90,95)、极好 [95,100]。不修改评分算法。

项目综合分沿用本人历史接口的聚合和回退规则：存在有效 project_member_score 时使用其项目均分，否则使用 collaboration_score 历史均分。另补充已发布且未删除项目的当前成员、离队成员及创建者记录，未评分返回 null；按项目去重。不额外公开未发布的无评分项目。旧 `/users/me/collaboration-history` 返回结构与行为不变。

无需数据库迁移，无新增小程序页面或路由。先发布后端新接口，再发布客户端。OpenAPI 源文件已更新；生成产物遵循仓库原有忽略规则，构建时使用现有生成工作流。
